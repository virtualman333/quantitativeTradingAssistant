## ui:dev 卡在「Vite 就绪」后不启动 Electron（IPv6/IPv4 地址族不一致）
- 现象：Vite 起来了但 Electron 一直不启动，卡在 waitPort。
- 根因：Vite 默认 `host=localhost` 在 Windows 解析到 IPv6 `::1`（netstat 显示 `[::1]:8088`），而 `dev-ui.mjs` 的 `waitPort`/`findFreePort` 用 `127.0.0.1`(IPv4) 探测，地址族不一致 → 永远等不到端口就绪。

- 经济学解释：ETH/BTC 比价 24h 动量 = 风险偏好的中期转变（资金涌入高 beta 资产），比纯技术因子（追涨杀跌）更有依据。
- 待办：①拉 1 年数据做更长验证 ②把该信号固化成可执行策略规则（接入 trading 专家或规则引擎）③注意 lb=12 负/24 正的参数敏感性，需明确"为什么是 24h"的机制。

- **最终结论（穷举 5 类因子后）**：技术因子 / 均值回归 / 资金费率 / 跨市场 lead-lag / 比价动量，在 1 年尺度下**全部无稳健 alpha**。简单公开因子的 alpha 早已被市场套利光（有效市场）。没有信息优势（消息速度/独有数据）就没有 alpha——这是现实，不是代码 bug。

1. **MCP 连接泄漏**（`src/main.ts`）：原 `conn.close()` 在 `graph.invoke` 之后、无 finally 保护，invoke 抛异常时 stdio MCP 子进程每轮泄漏累积 → 越跑越慢/卡死。改为 `try { invoke } finally { conn.close() }`。
2. **store 缓存永不刷新**（`src/store.ts` + `main.ts`）：agent 常驻进程 loadStore 有模块级 cache，界面改模型/角色/MCP 不生效。新增 `reloadStore()`（置 cache=null），`runRound` 每轮开头调用。同时修复 loadStore：损坏文件不再被 defaults 覆盖（原来 catch 分支会 saveStore(defaults) 覆盖损坏文件导致数据丢失），仅文件不存在时才创建。
3. **LLM fetch 无超时**（`src/llm.ts`）：decide 路径（专家/调度/拍板）的 fetch 无 timeout，网关挂起不响应会永久卡死整轮、agent 停摆。新增 `fetchWithTimeout()`（AbortController + 3 分钟超时），替换 OpenAICompatProvider.callOnce 与 AnthropicProvider.decide 的 fetch。
- 说明：流式 chat/portfolio 路径已有外部 signal 可中止，未改；fetchWithTimeout 覆盖「连接+headers」阶段，body 阶段的极端挂起未覆盖（概率低，如需再深化）。

## 修复「⚠ 'get' on proxy: property 'modelsList' is read-only and non-configurable」
- 现象：界面顶部红条报 `⚠ 'get' on proxy: property 'modelsList' is a read-only and non-configurable data property on the proxy target but the proxy did not return its actual value (expected 'function () { [native code] }' but got '(...args) => v(...args.map(flatten))')`。
- 根因：`ui/lib/api.js` 里 `export const api = new Proxy(window.api, { get(...) { return wrappedFn } })`——`window.api` 是 contextBridge 暴露的**冻结对象**（方法只读且不可配置），Proxy 的 get 对同一方法每次返回不同的包装函数，违反 JS Proxy 不变量，V8 抛 TypeError（不是 Vue 警告）。抛错被 `loadAll()` 捕获写入 `globalError`，显示为顶部 `⚠` 红条（App.vue 的 `⚠ {{ globalError }}`）。
- 修复：改为 `buildApi(window.api)`——用 `Object.getOwnPropertyNames` 显式枚举方法名，把「参数拍平包装函数」挂到**全新的普通对象**上（不再 Proxy 包冻结对象），避开不变量检查；拍平逻辑（renderer 侧 JSON 往返，解决 contextBridge structuredClone 克隆 Vue Proxy 报错）保持不变。
- 教训：**不能用 Proxy 包装 `window.api` / `Object.freeze` 过的对象并返回不同于原始值的新函数**；要包装就复制成一个新普通对象。之前的 renderer 侧拍平 Proxy 方案虽解决了克隆报错，但引入此 Proxy 不变量 TypeError。
