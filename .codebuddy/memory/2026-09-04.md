## 热门行情点击进新窗口显示首页 bug 修复
- 现象：点击「热门行情」交易对，新开窗口显示的是首页而非 K 线图。
- 根因：`electron/main.ts` 的 `loadUi()` dev 分支原来 `w.loadURL(devUrl + (hash ? "#" + hash : ""))`，而 `nav.js` 传的 hash 已带 `#`（形如 `#/win/kline?instId=xxx`），于是拼成 `##/win/kline?...` 双 `#` → `location.hash` 解析失败 → `parseRoute` 返回 null → `winRoute=null` → 独立窗口退化成渲染主界面（首页）。
- 修复：`loadUi` 统一先 `hash.replace(/^#/,"")` 去掉 #，各加载方式再自行加 #（dev 用 `devUrl + "#" + h`，dist 用 `loadFile(..., {hash: h})`）。dist 分支原逻辑本就正确（`hash.replace(/^#/,"")`），本次统一后两种模式都 robust。
- 复用窗口分支（`executeJavaScript("location.hash = ...")`）本就正确，未动。
- 独立窗口路由链路：nav.js `openKlineWin` → `#/win/kline?instId=...` → 主进程 `win:open` → `loadUi(w, hash)` → App.vue 按 `winRoute` 渲染 WinFrame。关键：hash 全程保持「带 # 一次」，不能在 loadURL 时二次加 #。

## 切换到对话页未滚动到底部 bug 修复
- 现象：切到「对话」页签，对话列表没自动滚到底部（最新消息处）。
- 根因：App.vue 用 `<KeepAlive>` 缓存视图，ChatView 只在 `onMounted` 里 `loadHistory()→scroll()`；切走再切回时组件已缓存，只触发 `onActivated`、不触发 `onMounted`，滚动位置停在切走前的位置。
- 修复：ChatView 补 `onActivated(() => scroll())`，KeepAlive 激活时重新滚到底部。scroll() 内部已用 nextTick，无需额外处理。
- 提醒：KeepAlive 缓存的视图，凡有「切回要刷新/复位」的逻辑（滚动、重拉数据），都要在 onActivated 里再做一次，不能只依赖 onMounted。

## 超短线开单失败修复（argparse help 含 % 触发格式化错误）
- 现象：开单报 `Command failed: python scripts/scalper.py ... Traceback ... argparse.py _check_help → formatter._expand_help`。
- 根因：`scalper.py` 的 `--fee-rate` help 字符串里 `默认 0.05%` 含 `%`，Python argparse 会把 help 当 `help % dict` 做格式化，`%` 触发 `unsupported format character`。**此坑历史已踩过**（memory 2026-09-04「非技术 alpha 源探索」：argparse help 含 % 需 `%%` 转义或去掉 %）。
- 修复：`0.05%` → `0.0005`（去掉 %）。`python scripts/scalper.py --help` 已验证不再报错。
- 顺手优化（开箱即用）：
  1. `kelly_rr` 重写：原「固定 f_target=0.16 反推 RR」在胜率 0.6 时算出 RR=0.91 被夹到 1.0 → 止盈=止损距离，扣双边手续费后负期望。改为「保本盈亏比 RR0=q/p 翻倍，夹在 [1.5,4]」：strong(p=0.6)→RR1.5、weak(p=0.52)→RR1.85，保证期望为正。
  2. `atrMult` 默认 1.5→2.5（store.ts DEFAULT_SCALPER + scalper.py argparse default）：1 分钟 BTC ATR≈0.085%，atrMult 太小则止损距离 < 手续费占比，期望恒负；2.5 时 strong 期望≈+0.005%/笔（超短线真实水平，靠高频累积）。

## 超短线循环不自动开仓修复（reloadStore 缺失）
- 现象：超短线循环未实现自动开仓。
- 根因：`main.ts` 的 `scalperTick()` 里直接 `getScalperConfig()`，而 `loadStore()` 有模块级 cache——agent 子进程启动时加载一次 store.json 后一直用内存缓存。UI 通过 electron 主进程 `scalper:update` 写 store.json，agent 子进程的 cache 不会自动更新。主轮次 `runRound()` 首行有 `reloadStore()` 所以能读最新配置，但 `scalperTick()` 漏了，导致：UI 里「启用」后 agent 仍读 enabled=false，循环永不触发开单。
- 修复：`scalperTick()` 开头加 `reloadStore()`（每次 tick 重读 store），使 UI 改配置 ≤ intervalSec 后生效。
- 附带修复：
  1. `scalper.ts` `scalpOnce()` 开头加 `--dry-run` 检查：演练模式下超短线不下单（与主轮次一致，避免 dry-run 误真单）。
  2. `main()` 启动时打印 `超短线循环已启动: enabled/inst/leverage/interval/useLlm` 日志，便于排查。
- 注意：改的是 agent 子进程代码（main.ts/scalper.ts），需 `npm run build` 重新编译 + 重启 agent（点「停止服务」再「启动服务」）才生效；仅重载 UI 不够。
- 教训：任何独立循环/定时器读 store 配置，都必须先 `reloadStore()`（store.ts 的 loadStore 有模块级 cache，跨进程不自动刷新）。
